## 三、P0 安全问题（6 条，优先修复）

### P0-1 手机号明文存储（✅ 已修复 2026-08-31）
- **位置**：`ResumeController.createOrUpdateResume` 112 行
- **问题**：简历保存路径里 `user.setPhone(phone)` 未 AES 加密，而 `AuthController.updateProfile` 是加密的，两处不一致。
- **风险**：走简历保存路径的手机号明文入库，敏感信息泄露。
- **修复**：已改为 `user.setPhone(aesUtil.encrypt(phone))`（现第 116 行），注入 `AESUtil`、补 import，与 AuthController 统一。

### P0-2 简历越权访问（✅ 已修复 2026-08-31）
- **位置**：`ResumeController.getMyResume` 65 行、`getStudentResume` 307 行
- **问题**：`getMyResume` 接受外部 studentId 不校验是否本人；`getStudentResume` 仅教师做班级校验，HR/学生/管理员直接跳过。
- **风险**：任何登录用户可查任意学生简历。
- **修复**：`getMyResume` 已改为强制用当前登录 userId、忽略外部 studentId；`getStudentResume` 已补全角色校验（教师查本班、学生查自己、HR 查投递本企业岗位的学生——新增注入 JobService/DeliveryService），管理员不受限。

### P0-3 文件删除路径穿越（✅ 已修复 2026-08-31）
- **位置**：`FileController.delete` 112 行
- **问题**：`fileUrl` 客户端可控，`replace(accessUrl, uploadPath)` 可被构造 `../` 路径。
- **风险**：可删除服务器任意文件。
- **修复**：已加 5 层防护——前缀白名单 + 拒绝 `..`/`\` + getCanonicalPath 规范化 + 校验仍在上传目录内 + 拒绝删除目录。

### P0-4 AES 密钥硬编码默认值（✅ 已修复 2026-08-31）
- **位置**：`AESUtil` 21-25 行
- **问题**：`@Value("${aes.key:recruitment-aes-key-12}")` 有默认值，未配置时用公开密钥。
- **风险**：敏感字段加密形同虚设。
- **修复**：去掉默认值（`${aes.key}` 强制配置）+ `init()` 校验密钥长度 ≥16 字节 + 加密改用随机 IV（密文格式 `v1:IV+密文`），解密兼容旧固定 IV 格式（`${aes.iv}` 可选，仅用于解密历史数据）。同步更新 application.yml / application-example.yml 增加 aes 配置。同时删除无引用的 `encryptBase64`/`decryptBase64` 死方法（其引用了重命名前的 `ivParameterSpec` 字段导致编译报错）。

### P0-5 JWT 黑名单未闭环（✅ 已修复 2026-08-31）
- **位置**：`JwtInterceptor`
- **问题**：拦截器不查 `blacklist:`，登出后 token 仍可访问其它接口（仅 `/auth/me` 手动校验）。
- **风险**：登出不生效。
- **修复**：在拦截器校验流程中新增第 5 步黑名单查询（`blacklist:{token}`），命中即返回 401。

### P0-6 班级信息越权（✅ 已修复 2026-08-31）
- **位置**：`ClassController.getClassById` 150 行、`getClassesByMajor` 177 行、`getClassesByGrade` 186 行
- **问题**：三个查询接口未做归属校验，任何登录用户可按 id/专业/年级查班级。
- **修复**：`getClassById` 补 `checkClassOwnership`（教师查自己班、管理员不受限）；`getClassesByMajor`/`getClassesByGrade` 补角色过滤（管理员看全部、教师只看自己班、其他角色 403）。

## 六、三个跨模块架构性问题（最值得关注）

### 1. 评分数据契约不统一（P2-7、P2-8）

AI 评分体系原是三处各自实现的，没有统一契约：
- 匹配分 `matchScore`：0-1 小数
- 评分 `score`：0-100
- 子维度：BatchResume 3 项、JobAnalysis 4 项、AIMatch 英文 key

**影响**：跨页面数据不可比、前端配色阈值两套、改一处要改三处。

**已修复（2026-08-31）**：新建 `frontend/src/utils/score.js` 统一契约层，提供 `matchScoreToPercent`（0-1 → 0-100）、`parseScoreDetail`（兼容中文/英文 key，输出统一 `{total, comment, dims}`）、`scoreColor`/`scoreTag`（统一 90/75 阈值）、`dimLabel`、`normalizeScore`。AIMatch / BatchResume / JobAnalysis 三个页面已接入，删除各自散落的 `matchPercent` / `scoreColor` / `dimLabel` / `dimMap` 实现。展示层分数统一 0-100，颜色阈值统一「>=90 优秀 / >=75 合格 / 其余待提升」。

### 2. 前端 store 层名存实亡（P2-10）

建了 4 个 Pinia store，但页面全部绕过 store 直接调 api，导致 store 里的 ReferenceError bug 一直没暴露。

**已修复（2026-08-31）**：删除 app.js / job.js / resume.js 三个死 store，保留 user.js（被布局与业务页面使用）。页面继续直接走 api，状态管理职责收敛到 user.js。

### 3. 分页形同虚设（P2-5）

前端普遍"后端一次拉全量、前端 slice"，`page/size` 参数是摆设。

**建议**：后端补分页插件，前端传真实分页参数。
