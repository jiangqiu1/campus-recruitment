# 投递模块 · 状态机与消息联动（深度补充）

> 本文档基于 `DeliveryServiceImpl.java` 源码，记录投递状态机的完整流转、消息触发点与数据级权限。

## 1. 状态机定义（DeliveryStatusEnum）

| 状态码 | 语义 | 触发动作 |
|--------|------|---------|
| 0 | 已投递（待查看） | `deliverResume` 创建 |
| 1 | 简历被查看 | `updateDeliveryStatus(1)` |
| 2 | 面试（待面试） | `updateDeliveryStatus(2)` 或 `arrangeInterview` |
| 3 | 录用 | `updateDeliveryStatus(3)` |
| 4 | 未通过 | `updateDeliveryStatus(4)` |

```
0 已投递 ──► 1 简历被查看 ──► 2 面试 ──► 3 录用
                                   └──► 4 未通过
```

## 2. 投递流程（deliverResume，76 行）

```
① 校验学生身份：user.getRole() == 0，否则抛异常
② 防重复投递：查 status=0 的记录，anyMatch(jobId 相同) → 抛异常
③ 创建 Delivery：status=0、resumeVersion、createTime
④ 生成投递成功消息（message 表）
```

**防重复逻辑细节**：只查 `status=0` 的记录（83 行），意味着被拒（status=4）后可重新投递。

## 3. 状态流转与消息触发（updateDeliveryStatus，114 行）

每次状态变更，按 `switch(status)` 触发不同的消息：

| status | 学生端消息（message 表） | HR 端消息（user_message 表） |
|--------|------------------------|---------------------------|
| 1 | "简历已被企业查看，祝您好运" | 无 |
| 2 | "面试邀请：已通过初筛，面试安排：{地点}" | "{学生} 投递「{岗位}」已进入面试阶段" |
| 3 | "录用通知：您已被录用" | "{学生} 已被「{岗位}」录用" |
| 4 | "未通过通知：未通过筛选" | "{学生} 投递「{岗位}」未通过筛选" |

**注意**：`status == 2` 时会**自动设置面试信息**（128-129 行）：`interviewTime = now + 1小时`、`interviewLocation = "线上面试（腾讯会议）"`。若走 `arrangeInterview`（232 行）则用 HR 指定的时间地点。

## 4. 消息联动架构（双表）

| 表 | 接收方 | 写入方法 |
|----|--------|---------|
| message | 学生 | `createMessage`（184 行） |
| user_message | HR（管理员/教师） | `notifyHrOfJob`（203 行）→ `userMessageService.sendMessage` |

`notifyHrOfJob`（203 行）逻辑：查该岗位公司的所有 HR（`companyId` 匹配 + `role=2`），逐个发 `user_message`。

## 5. 事务

`deliverResume`（75 行）、`updateDeliveryStatus`（113 行）、`arrangeInterview`（231 行）均标注 `@Transactional(rollbackFor = Exception.class)`，保证状态变更 + 消息写入的原子性。

## 6. 数据级权限

教师视角（`DeliveryController.getAllDeliveries` 69 行）：先查本班学生 id 列表，再过滤投递记录，教师只能看本班学生的投递。

## 7. N+1 优化

`enrichDeliveries`（`DeliveryController` 299 行）：组装 VO 时用 `listByIds` 批量查询学生/岗位/企业/评分，避免逐条查询；同时过滤 role != 0 的异常投递。

## 8. 面试安排（arrangeInterview，232 行）

HR 指定面试时间、地点，写入 delivery（status=2）。与 `updateDeliveryStatus(2)` 的区别：前者用 HR 指定值，后者用默认值（+1 小时、腾讯会议）。
