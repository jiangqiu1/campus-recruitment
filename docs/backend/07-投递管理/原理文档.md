# 投递管理模块 · 原理文档

> 说明投递状态机、消息联动通知、数据级权限与 N+1 查询优化。

## 1. 设计目标

- 投递全生命周期可追踪：待查看 → 邀约 → 面试 → 录用/拒绝。
- 状态变更自动联动消息通知（学生 + HR 双向）。
- 教师只能看本班学生的投递（数据级权限）。

## 2. 投递状态机

```
0 已投递 ──► 1 简历被查看 ──► 2 面试 ──► 3 录用
                                 └──► 4 未通过
```

> 详细流转与消息触发点见同目录 `状态机与消息联动.md`。

`updateDeliveryStatus`（114 行）驱动状态流转，每次变更触发消息联动。

## 3. 投递流程

`deliverResume`（76 行）：

1. 校验当前用户为学生身份。
2. **防重复投递**：同一学生对同一岗位已投递则拒绝。
3. 生成投递成功消息通知学生。
4. 通知 HR 有新投递（`notifyHrOfJob` 203 行）。

## 4. 消息联动

`updateDeliveryStatus`（114 行）在状态流转后，通过 `createMessage`（184 行）分别通知学生和 HR（如"你的投递已进入面试环节"）。

## 5. 数据级权限

`getAllDeliveries`（76-94 行）：教师只返回本班学生的投递记录（先查本班学生 id 列表，再过滤）。

## 6. N+1 查询优化

`enrichDeliveries`（299 行）：组装 VO 时用 `listByIds` 批量查询学生/岗位/企业/评分，避免逐条查询（消除 N+1）。同时过滤掉非学生角色（role != 0）的异常投递记录。

## 7. 面试安排

`arrangeInterview`（185 行 / 232 行）：HR 安排面试时间、地点，写入 delivery 并通知学生。
