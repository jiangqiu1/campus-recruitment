# 岗位模块 · 三层权限详解（深度补充）

> 本文档基于 `JobController.java` 源码，记录岗位模块三层权限（路由级/接口级/数据级）的完整实现。岗位模块是全项目三层权限体现最完整的模块，是理解权限体系的范本。

## 1. 三层权限总览

| 层级 | 实现位置 | 作用 |
|------|---------|------|
| 路由级（认证） | `JwtInterceptor` + `WebConfig` | 未登录一律 401 |
| 接口级（角色） | `BaseController.requireXxx()` + 各方法内 `role` 判断 | 某角色能否调用某操作 |
| 数据级（隔离） | `getAllJobs` 内的 `query.eq(...)` | 某角色能看到哪些数据 |

## 2. 数据级权限（getAllJobs，45 行）

```java
if (Objects.equals(role, 2)) {
    // HR：只看自己企业的岗位
    SysUser currentUser = userService.getById(userId);
    if (currentUser != null && currentUser.getCompanyId() != null) {
        query.eq(Job::getCompanyId, currentUser.getCompanyId());
    } else {
        query.eq(Job::getCreatedBy, userId);   // HR 无企业归属时退化为只看自己创建的
    }
} else if (!Objects.equals(role, 3)) {
    // 非管理员非HR（教师/学生）：只看已发布
    query.eq(Job::getStatus, 1);
}
// 管理员（role=3）：无限制
```

| 角色 | 数据范围 |
|------|---------|
| 管理员（3） | 全部岗位 |
| HR（2） | 本企业岗位（companyId 匹配） |
| 教师（1）/ 学生（0） | 仅 status=1 已发布 |

> 教师另有专用接口 `/jobs/teacher`（getTeacherJobs，166 行），返回自己创建的**所有状态**岗位（含草稿/关闭），与通用 `/jobs` 的"只看到已发布"互补。

## 3. 接口级权限（各操作的角色规则）

| 操作 | HR（2） | 教师（1） | 管理员（3） |
|------|---------|----------|------------|
| createJob（212） | 可，自动归属本人，status=0 | 可，须关联企业 | 无权限（走 else 403） |
| updateJob（245） | 可，同企业 | **不可**（403） | 可（未显式拦截） |
| publishJob（279） | checkJobOwnership | checkJobOwnership | checkJobOwnership |
| closeJob（294） | 同企业才可 | 可**强制关闭任何**岗位 | 未显式拦截 |
| pauseJob（323） | 同企业才可 | 未显式拦截 | 未显式拦截 |
| deleteJob（346） | 同企业，且草稿/关闭 | 自己创建，且草稿/关闭 | 未显式拦截 |

**关键细节**：

- `closeJob`（294 行）教师可**强制关闭任何岗位**（监管干预），这是教师特有的越权操作。
- `deleteJob`（346 行）只能删草稿（status=0）或已关闭（status=2），防止误删在招岗位。
- `updateJob`（245 行）教师被明确禁止编辑企业岗位内容（"教师不可编辑企业岗位内容"）。

## 4. 两个核心私有方法

### 4.1 checkJobOwnership（381 行）—— 通用归属校验

```java
if (Objects.equals(role, 3)) return;               // 管理员放行
if (Objects.equals(role, 1) || Objects.equals(role, 2)) {
    if (isSameCompanyHr(userId, job.getCreatedBy())) return;   // 自己 或 同企业
}
throw new BusinessException(403, "无权操作此岗位");
```

### 4.2 isSameCompanyHr（402 行）—— 同企业判断

```java
if (Objects.equals(userId1, userId2)) return true;          // 同一个人
SysUser user1 = userService.getById(userId1);
SysUser user2 = userService.getById(userId2);
if (user1.getCompanyId() == null || user2.getCompanyId() == null) return false;
return Objects.equals(user1.getCompanyId(), user2.getCompanyId());   // companyId 相同
```

**值得注意**：此方法虽名"同企业 HR"，但教师（role=1）也走这里。教师无 `companyId`，所以教师之间判断恒为 false（除非 userId 相同）——这隐式实现了"教师只能操作自己创建的岗位"。

## 5. 权限规则速查表

| 场景 | 判定依据 | 结果 |
|------|---------|------|
| 教师操作自己创建的岗位 | isSameCompanyHr(userId, userId) | 通过（userId 相同） |
| 教师操作其他教师的岗位 | 两教师 companyId 均 null | 拒绝 |
| HR 操作同企业 HR 的岗位 | companyId 相同 | 通过 |
| HR 操作其他企业 HR 的岗位 | companyId 不同 | 拒绝 |
| 管理员操作任何岗位 | role=3 提前 return | 通过 |

## 6. 已知问题

- `pauseJob`（323 行）未对教师/管理员做显式角色限制，理论上任何通过路由认证的角色都能走到（依赖前端控制）。`updateJob`、`deleteJob` 对管理员是"未显式拦截"而非"显式放行"，逻辑上依赖其它约束，建议后续统一为显式白名单。
