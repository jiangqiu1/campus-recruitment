# 岗位管理模块 · 原理文档

> 说明岗位状态流转、三层权限在岗位模块的体现、岗位变更申请流程。

## 1. 设计目标

- 岗位生命周期可管理：草稿 → 发布 → 关闭/暂停。
- 三层权限（路由/接口/数据）在岗位模块体现最完整。
- HR 修改岗位需走"变更申请 + 教师审核"，保证岗位信息质量。

## 2. 岗位状态流转（状态机）

```
草稿 ──publishJob──► 已发布 ──closeJob──► 已关闭
  ▲                      │
  │                      └──pauseJob──► 已暂停（可重新发布）
  │
  └── 删除仅限草稿/已关闭状态
```

- `JobServiceImpl.publishJob`（55 行）：草稿/关闭/暂停 → 已发布。
- `closeJob`（83 行）、`pauseJob`（95 行）分别流转到关闭/暂停。
- 删除仅限草稿/关闭状态（防止误删在招岗位）。

## 3. 三层权限的典型体现

| 层级 | 实现 |
|------|------|
| 路由级 | 所有岗位接口都过 JWT 拦截器 |
| 接口级 | 教师只能创建/删除自己的岗位；HR 只能操作自己或同企业 HR 的岗位（`isSameCompanyHr` 402 行判断 companyId 是否相同） |
| 数据级 | `getAllJobs`（56-64 行）：HR 只看本企业岗位（`eq(companyId)`），非管理员非 HR 只看 `status=1` 已发布 |

## 4. 岗位变更申请流程

```
HR 提交变更（submit 101）──► 教师审核（approve 119 / reject 136）
                                  │
                        通过 ──► 应用变更到岗位
                        拒绝 ──► 通知 HR 修改
```

- HR 不能直接改岗位，需提交 `job_change_apply` 变更申请。
- 教师审核通过后才生效，保证岗位信息可控。

## 5. 计数与推荐

- `incrementViewCount`（48 行）：浏览时计数 +1。
- `countDeliveries`（111 行）：投递计数。
- `getRecommendJobs`（435 行）：基于 AI 关键词为学生推荐岗位。

## 6. 溯源与二维码

- `generateTraceId`（116 行）：岗位生成溯源 ID。
- `generateQrCode`（122 行）：二维码生成（当前为占位 URL，待实现）。
