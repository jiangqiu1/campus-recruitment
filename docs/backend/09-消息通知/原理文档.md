# 消息通知模块 · 原理文档

> 说明两套消息系统、消息触发点与收藏机制。

## 1. 设计目标

- 站内消息分两套：学生端 `message` 与通用端 `user_message`，互不干扰。
- 业务事件（投递、评分、审核等）自动触发消息，无需用户主动查询。

## 2. 两套消息系统

| 系统 | 表 | 面向对象 | Controller |
|------|----|---------|-----------|
| 学生端消息 | message | 学生 | MessageController |
| 通用消息 | user_message | 管理员/教师/HR | UserMessageController |

> 注：`user_message` 表是后期迁移脚本新增的，用于补齐管理员/教师/HR 的消息能力；学生端沿用早期 `message` 表。

## 3. 消息触发点（跨模块联动）

消息不是独立产生的，而是在各业务模块中通过 `createMessage`（如 `DeliveryServiceImpl.createMessage` 184 行）联动触发：

| 业务事件 | 触发的消息 |
|---------|-----------|
| 投递成功 | 通知学生"投递成功" |
| 状态流转 | 通知学生 + HR"已邀约/面试/录用" |
| 企业审核 | 通知企业 HR"审核通过/拒绝" |
| 简历评分 | 通知学生 + HR 评分结果 |

## 4. 未读机制

- `getUnreadCount`：查询未读消息数（前端红点提示）。
- `markAsRead` / `readMessage`：单条标记已读。
- `markAllRead`（UserMessageController 58 行）：一键全部已读。

## 5. 岗位收藏

`favorite` 表记录学生对岗位的收藏（user_id + job_id），支持添加/取消/列表，用于学生"收藏岗位"功能。
