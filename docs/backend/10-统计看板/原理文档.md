# 统计看板模块 · 原理文档

> 说明三角色 Dashboard 的视角隔离、趋势聚合优化与演示数据兜底。

## 1. 设计目标

- 每个角色看到自己的数据：学生看个人进展，教师看班级就业，HR 看企业招聘，管理员看全局。
- 趋势类数据一次性聚合，避免循环查询。

## 2. 三角色视角

| 方法 | 视角 | 核心指标 |
|------|------|---------|
| `getStudentOverview`（61） | 学生 | 我的投递数、面试数、录用数 |
| `getTeacherDashboard`（126） | 教师 | 本班投递趋势、就业率、学生进度 |
| `getHrDashboard`（247） | HR | 本企业岗位、投递漏斗、评分分布 |
| `getOverview`（113） | 管理员 | 全平台用户/岗位/企业统计 |

## 3. 趋势聚合优化

`getDeliveryTrend`（321 行）用一次 `GROUP BY DATE(create_time)` 得到 7 天每天的投递数，而不是循环 7 次 count 查询。`getStatusValue`（531 行）、`getDayLabel`（541 行）负责状态映射与日期标签格式化。

## 4. 已知问题

- **随机数兜底**：`getEmploymentDistribution`（403 行）、`getScoreDistribution`（442 行）内部用 `Math.random()` 生成演示数据，真实数据接入后需移除。
- 看板数据依赖前端 ECharts 渲染，后端只返回聚合后的 JSON。

## 5. 数据来源

看板数据聚合自：投递（delivery）、岗位（job）、企业（company）、简历评分（resume_score_log）、人岗匹配（job_match_record）等表，是多个业务模块数据的汇总视图。
