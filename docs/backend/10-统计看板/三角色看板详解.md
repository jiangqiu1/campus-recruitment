# 统计看板模块 · 三角色看板详解（深度补充）

> 本文档基于 `StatisticsController.java` 源码，记录四视角 Dashboard、趋势聚合优化与已知问题。

## 1. 四视角 Dashboard

| 方法 | 视角 | 核心指标 |
|------|------|---------|
| `getStudentOverview`（61） | 学生 | 推荐岗位数、我的投递、被查看数、面试数、offer 数 |
| `getOverview`（113） | 管理员 | 总用户/总企业/活跃岗位/总投递 |

| `getHrDashboard`（247） | HR | 在招岗位、待处理简历、今日新增、今日面试、录用数 |

## 2. HR 视角的数据隔离

`getHrDashboard`（247 行）先取当前 HR 的 `companyId`，再 `eq(Job::getCompanyId, companyId)` 过滤本企业岗位，投递也按 `in(jobIds)` 过滤——数据级权限。

## 3. 趋势聚合优化（getDeliveryTrend，321 行）

这是全项目最有价值的 SQL 优化之一：

```java
// 单次 GROUP BY 查询，替代 7 次循环 count
.select("DATE(create_time) as day, COUNT(*) as cnt")
.in("job_id", jobIds)
.apply("create_time >= {0}", sevenDaysAgo.atStartOfDay())
.groupBy("DATE(create_time)")
```

一次查询得到 7 天每天的投递数，再映射到 7 个数组位，前端拿 `label/value/height` 直接画柱状图。

## 4. 已知问题（重要）

### 4.1 状态映射 bug（getStatusValue，531 行）（已修复 2026-08-31）

```java
case "已录用": return 3;   // ACCEPTED
case "面试中": return 2;   // INTERVIEW
case "待查看": return 0;   // PENDING
case "未录用": return 4;   // REJECTED
```

**与 `DeliveryStatusEnum`（0 待查看/1 已查看/2 面试中/3 已录用/4 不合适）已对齐**。原映射整体错位 +1 且「待查看」误落到 default，现已修正。

## 5. 热门岗位与近期动态

- `getHotJobs`（458 行）：取前 10 活跃岗位，按投递量排序，返回词云数据（name/count/size）。
- `getRecentActivities`（488 行）：优先取操作日志（LIMIT 10），为空时兜底取最近投递。
