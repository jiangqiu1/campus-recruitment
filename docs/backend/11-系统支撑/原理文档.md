# 系统支撑模块 · 原理文档

> 说明系统设置、文件存储、数据导出、操作日志 AOP、浏览历史的机制。

## 1. 系统设置（SettingsController）

- `sys_settings` 表用「分组 key + 设置 key + JSON 值」存储，支持基础/安全/通知三组。
- `getSettings`（26 行）读取时过滤敏感字段：security 组仅返回 `jwtExpiration`，不泄露密钥等。
- 保存均需 `requireAdmin()`（接口级权限）。

## 2. 文件存储（FileController）

- `upload`（38 行）：校验文件类型（简历 PDF、头像 JPG/PNG），按日期分目录本地存储，返回访问路径。
- 文件访问路径由 `application.yml` 的 `file.upload-path` 与 `base-url` 配置。

## 3. 数据导出（DataExportController）

- `export`（54 行）：支持 student / company / job / delivery / resume 五类数据，xlsx / csv / pdf 三种格式；教师/管理员可导出（角色校验）。
- PDF 导出需 `loadChineseFont`（248 行）加载中文字体，避免中文乱码。
- 依赖 Apache POI（xlsx）、OpenPDF（pdf）。

## 4. 操作日志 AOP（LogOperationAspect）

原理：用 `@Around("@annotation(LogOperation)")` 环绕切面，业务方法执行后自动记录日志，无需侵入业务代码。

- `around`（33 行）：执行原方法，记录耗时，成功/失败都保存日志。
- `saveLog`（58 行）：从 request attribute 取 userId，`getRemoteAddr` 取 IP，组装 `OperationLog`。
- `resolveTargetId`（100 行）：自动从方法参数中提取名为 `id`/`*id` 的参数作为业务 ID。
- 操作类型 = `type + ":" + value`（如 `OPERATION:创建岗位`）。

> 已知问题：日志同步写库（在业务线程内 save），高并发会拖慢响应，建议异步化。

## 5. 浏览历史（BrowseHistoryController）

- 学生浏览岗位时记录浏览历史，支持列表/删除/清空/批量删除。
- 数据可用于"最近浏览"与个性化推荐。

## 6. 模块定位

本模块承载通用能力（设置、文件、导出、日志、历史），被各业务模块复用，是系统的"横切"支撑层。
