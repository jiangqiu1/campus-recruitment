# AI 模块 · 原理文档

> 说明 AI 集成的调用方式、Prompt 设计、容错与降级机制，以及各 AI 场景的业务流程。
> 五个场景的完整 Prompt 原文与 JSON 字段结构，见同目录 `Prompt与字段规范.md`。

## 1. 设计目标

- **统一管道**：所有 AI 任务走同一个 `callAI`，避免重复代码。
- **结构化输出**：强制 LLM 返回 JSON，降低解析成本。
- **演示友好**：无 API Key 时 mock 降级，系统可离线演示。
- **可追溯**：解析、评分、匹配均有日志表记录，支持置信度统计与人工校正。

## 2. 统一调用管道（callAI，158 行）

**HTTP 调用**：
- 用 `RestTemplate.postForEntity(apiUrl, request, Map.class)` 调 DeepSeek Chat Completions。
- 请求头：`Content-Type: application/json`、`Authorization: Bearer {apiKey}`。
- 请求体：`model=deepseek-chat`、`temperature=0.3`、`max_tokens=1024`、`messages=[{role:user, content:prompt}]`。
- 配置来源：`application.yml` 的 `ai.api.key/url/model`。

**降级判断**：若 `apiKey` 为空或为 `sk-placeholder`，直接返回 `fallbackMock(taskName)`。

**响应解析**：取 `body.choices[0].message.content`。

## 3. Prompt 强制 JSON

每个任务方法（scoreResume / matchJob / parseResume / parseJobDescription / analyzeResume）的 prompt 末尾都写死：

```
请严格按以下 JSON 格式返回…只返回 JSON，不要包含其他文字。
```

并附带 JSON 字段与取值说明的模板。这样 LLM 输出更可控，解析更稳定。

## 4. JSON 容错解析（parseJsonResponse，201 行）

1. 去除 ```json 与 ``` 代码围栏标记。
2. 用 `indexOf('{')` 到 `lastIndexOf('}')` 截取第一个 `{` 到最后一个 `}` 之间内容。
3. `ObjectMapper.readValue` 反序列化为 Map。
4. 任何异常 → 返回 `fallbackMock(taskName)`。

## 5. mock 降级（fallbackMock，225 行）

按 taskName 返回预置模拟 Map：

| 任务 | mock 示例 |
|------|----------|
| scoreResume | 总分 78、技能 82、经验 72、学历 80 |
| matchJob | 匹配分 82、各维度 85/80/72/78 |
| parseResume | 空字段模板 |
| parseJob | 前端开发样例 |
| analyzeResume | 72 分 + 改进建议 |

## 6. 五大 AI 能力与业务流

| 能力 | 方法 | 业务流 |
|------|------|--------|
| 简历评分 | `scoreResume` | 拼简历文本 → 调 AI → 得分 + 子维度 → 写 resume_score_log → 通知学生/HR |
| 人岗匹配 | `matchJob` | 删旧记录 → 拼简历+岗位文本 → 调 AI → matchScore/100 存 0-1 → 写 job_match_record |
| 简历解析 | `parseResume` | 教师触发 → 调 AI 抽 16 字段 → 按填充率算置信度 → 写 ai_parse_log |
| 岗位解析 | `parseJobDescription` | 粘贴 JD → 调 AI 抽标题/薪资/地点/技能 → 自动填表单 |
| 简历分析 | `analyzeResume` | 调 AI 给优点/缺点/建议 → 存回 resume.ai_analysis |

## 7. 置信度与人工校正

`AiParseController.parse`（124 行）按解析字段的填充率估算置信度，写入 `ai_parse_log.confidence_score`。支持按置信度区间查询未校正记录，教师可 `correctParseResult` 人工校正——形成「AI 解析 → 置信度 → 人工校正」的闭环。

## 8. token 控制

`truncate`（300 行）统一截断输入文本：简历评分/匹配截 2000 字符，解析截 3000 字符，控制 token 消耗。

## 9. 已知问题

- **无超时配置**：RestTemplate 默认无超时，AI 慢响应会占用线程，建议加超时 + 连接池。
- **失败与降级混淆**：API 调用失败（非「未配 Key」）也返回 mock 假数据，真实系统应区分「未配置 → mock」与「调用失败 → 报错」。
- **AiFeedbackLog 未成体系**：有 Entity+Mapper 但无 Service/Controller，XML 字段与实体不一致。
