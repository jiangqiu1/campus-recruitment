# AI 双模型接入 + 学生 AI 助手（2026-09-30）

> 本次改造：①AiService 双模型通道（DeepSeek + 智谱 GLM）②每次 AI 调用元数据落库（毕设对比实验数据源）③学生向 AI 助手接口（简历诊断 / 模拟面试）④简历诊断防重复缓存。
> 五个原有场景的 Prompt 细节见同目录 `Prompt与字段规范.md`（其配置段描述已由本文档更正）。

## 1. 双模型配置（AiProperties）

配置类：`config/AiProperties.java`，`@ConfigurationProperties(prefix = "ai")`。

```yaml
ai:
  default-provider: deepseek   # 智谱 key 配好后改为 glm
  providers:
    deepseek:
      key: sk-xxx
      url: https://api.deepseek.com/v1/chat/completions
      model: deepseek-chat
    glm:
      key: xxx.yyy
      url: https://open.bigmodel.cn/api/paas/v4/chat/completions
      model: glm-4.5-flash
```

- 旧键 `ai.api.key/url/model` **已废弃**（对应旧版 3 个 `@Value` 字段已删除）。
- 某 provider 的 key 缺失（空或 `sk-placeholder`）时，该通道调用自动降级 `fallbackMock`，系统可离线演示。

## 2. callAI 调用管道变化（AiService）

- `callAI(prompt, taskName)` → 默认 provider、max_tokens=1024（签名不变，5 个旧场景零改动）。
- 新增内部重载 `callAI(prompt, taskName, providerName, maxTokens)`；模拟面试出题用 max_tokens=2048。
- `parseJsonResponse` 解析失败改返回 null，由 callAI 统一降级并记 mock 标记。

### 调用日志（多模型对比实验数据源）

**每次调用（含降级 mock）写一条 `ai_parse_log`**，新增字段（迁移脚本 `backend/sql/migration-20260930-ai-provider.sql`，需执行）：

| 字段 | 说明 |
|------|------|
| `provider` | deepseek / glm（降级时记录尝试的通道） |
| `task_name` | scoreResume / matchJob / parseResume / parseJob / analyzeResume / genQuestions / evalAnswer |
| `latency_ms` | 调用耗时毫秒 |
| `user_id` | 发起用户（RequestContextHolder 尽力获取；旧 `teacher_id` 仅存量解析数据使用） |
| `mock_flag` | 1=降级 mock（含 key 缺失、HTTP 失败、JSON 解析失败） |

写日志整体 try-catch，日志失败只 warn 不影响主流程。raw_message 存 prompt 前 300 字，parsed_result 存响应前 2000 字。

## 3. 新增 AI 场景（学生向）

| 方法 | taskName | 输入 | 返回 JSON |
|------|----------|------|-----------|
| `generateInterviewQuestions` | `genQuestions` | jobTitle/jobDescription/jobRequirements/resumeText/count | `{questions: [{id, type: "技术\|项目\|行为", question}]}` |
| `evaluateAnswer` | `evalAnswer` | jobTitle/question/answer/resumeText | `{score: 0-100, comment, betterAnswer}` |

Prompt 风格与旧场景一致（严格 JSON + 「只返回 JSON，不要包含其他文字」），`fallbackMock` 已补两个 case（5 道模拟题 / 75 分点评）。

## 4. 学生 AI 助手接口（AiAssistantController，新文件）

`/ai-assistant/**`，全部 `requireStudent()`（BaseController 新增方法，role≠0 → 403），**不接收外部 studentId，一律用当前登录学生**（P0-2 同款防越权）：

| 接口 | 入参 | 逻辑 |
|------|------|------|
| `POST /resume-review` | `{force?}` | 取自己简历（无简历 404）→ `resumeService.analyzeWithCache(resume, force)` |
| `POST /interview/questions` | `{jobId}` | 校验岗位存在 → 取自己简历（可空）→ `generateInterviewQuestions(…, 5)` |
| `POST /interview/evaluate` | `{jobId, question, answer}` | 校验岗位 + 非空作答 → `evaluateAnswer` |

JWT 拦截器覆盖 `/**`，WebConfig 无需改动。

## 5. 简历诊断防重复缓存（ResumeService.analyzeWithCache）

教师 `POST /ai-parse/analyze-resume` 与学生 `POST /ai-assistant/resume-review` 共用此方法：

- 诊断结果写回 `resume.aiAnalysis` 时附 `analyzedAt` 时间戳（与 updateTime 同值写入）；
- 再次诊断：`analyzedAt ≥ updateTime`（1 分钟容差，防同刻写入竞态/DB 秒级精度偏差）且未带 `force=true` → **直接返回缓存结果**，message 为「简历未变更，已返回最近诊断结果」，data 带 `cached: true`，不调 AI；
- 简历已变更（updateTime 晚于 analyzedAt 超 1 分钟）或 `force=true` → 重新调 AI，返回 `cached: false`；
- 旧数据 aiAnalysis 无 `analyzedAt` 视为过期；
- 教师端入参新增 `force`；模拟面试出题**不缓存**（每次练习出新题是预期行为）。
