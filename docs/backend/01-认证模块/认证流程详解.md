# 认证模块 · 认证流程详解（深度补充）

> 本文档基于 `JwtUtil.java`、`AuthController.java`、`JwtInterceptor.java` 源码，记录 JWT 生成/校验的完整代码流程、claim 结构、Redis key 读写时序。

## 1. JWT 生成（JwtUtil.generateToken，52 行）

```java
public String generateToken(Long userId, String username, String role, String tokenVersion) {
    Date now = new Date();
    Date expiryDate = new Date(now.getTime() + expiration);  // expiration = 604800000ms = 7 天

    Map<String, Object> claims = new HashMap<>();
    claims.put("userId", userId);
    claims.put("username", username);
    claims.put("role", role);
    claims.put("tokenVersion", tokenVersion != null ? tokenVersion : "1");

    return Jwts.builder()
            .setClaims(claims)
            .setIssuedAt(now)
            .setExpiration(expiryDate)
            .signWith(getSigningKey())   // HS256，Keys.hmacShaKeyFor(secret.getBytes())
            .compact();
}
```

**claim 结构**：

| claim | 类型 | 说明 |
|-------|------|------|
| userId | Long | 用户 ID |
| username | String | 用户名 |
| role | String | 角色（"0"/"1"/"2"/"3"） |
| tokenVersion | String | 版本号（null 时默认 "1"） |
| iat | Date | 签发时间（标准） |
| exp | Date | 过期时间（标准，7 天） |

**注意**：`getSigningKey`（36 行）用 `Keys.hmacShaKeyFor(secret.getBytes(UTF_8))`，HS256 要求 secret 至少 32 字节，否则抛异常（配置层面的隐患）。

## 2. 登录时序（AuthController.login，49 行）

```
① userService.login(username, password, role)  校验身份
② tokenVersion = UUID.randomUUID().去横线().substring(0,12)
③ redisUtil.setWithExpire("token:version:{id}", tokenVersion, 7天)
④ token = jwtUtil.generateToken(id, username, role, tokenVersion)
⑤ redisUtil.setWithExpire("token:{id}", token, 7天)
⑥ 返回 prefix + token（"Bearer " + token）+ LoginResponse
```

**LoginResponse 字段**：token、userId、username、realName、role、avatarUrl、companyId。

## 3. 拦截器校验（JwtInterceptor.preHandle，37 行）

8 步校验的代码级时序：

```
① 取 Authorization 头，校验非空且以 "Bearer " 开头
② token = token.substring(prefix.length())        去前缀
③ claims = jwtUtil.getClaimsFromToken(token)       解析（失败=null）
④ jwtUtil.isTokenExpired(token)                    过期判断
⑤ redisUtil.get("blacklist:{token}")               黑名单：已登出 → 拒绝（2026-08-31 新增）
⑥ redisUtil.get("token:{userId}")                  单端登录：存在且≠当前 token → 拒绝
⑦ redisUtil.get("token:version:{userId}")          版本号：与 claim.tokenVersion 不一致 → 拒绝
⑧ request.setAttribute("userId"/"username"/"role")  通过，写入上下文
```

## 4. 登出（AuthController.logout，99 行）

```
token 从 request body 取（非 header）
token = token.substring(prefix.length())  去前缀
redisUtil.setWithExpire("blacklist:" + token, "1", 7天)
```

**注意**：黑名单 key 是 `blacklist:{完整token字符串}`，TTL 与 token 剩余有效期的对齐方式是"统一 7 天"。

## 5. 改密码失效（AuthController.updatePassword，193 行）

```
① userService.updatePassword(userId, oldPwd, newPwd)  校验旧密码后更新
② newVersion = UUID.randomUUID().去横线().substring(0,12)  重新生成（非递增）
③ redisUtil.setWithExpire("token:version:{id}", newVersion, 7天)  覆盖
```

改密码后，旧 token 的 claim 里还是旧 `tokenVersion`，在拦截器第 ⑥ 步被拒。

## 6. 三种失效机制对比

| 机制 | 触发 | 实现 | 是否闭环 |
|------|------|------|---------|
| 过期 | 时间到 | exp 标准 claim | 是（拦截器第④步） |
| 单端登录 | 新登录 | `token:{userId}` 覆盖 | 是（拦截器第⑤步） |
| 改密码 | 改密码 | `token:version:{userId}` 覆盖 | 是（拦截器第⑥步） |
| 登出 | 主动登出 | `blacklist:{token}` | **是**（拦截器第⑤步查黑名单，已修复 2026-08-31） |

## 7. 已知问题

1. ~~**黑名单未闭环**~~（已修复 2026-08-31）：`JwtInterceptor` 现已新增第⑤步黑名单查询（`blacklist:{token}`），登出后的 token 会被拦截器拒绝。
2. **secret 无长度校验**：HS256 需 ≥32 字节，配置过短会在启动后首次签发时抛异常。
3. **手机号解密**：`getUserInfo`（115 行）返回前解密手机号，失败则忽略（`catch (Exception ignored)`），保证接口不因解密异常中断。
