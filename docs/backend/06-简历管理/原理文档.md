# 简历管理模块 · 原理文档

> 说明简历的存储结构、PDF 解析流程、数据级权限与默认简历机制。

## 1. 设计目标

- 简历支持结构化编辑 + PDF 上传两种录入方式。
- 学生可维护多份简历，投递时用默认简历。
- 教师只能查看本班学生的简历（数据级权限）。

## 2. 简历存储结构

`resume` 表用 JSON 字段存结构化内容：

| 字段 | 内容 |
|------|------|
| education | 教育经历（JSON） |
| internship | 实习经历（JSON） |
| project | 项目经历（JSON） |
| ai_analysis | AI 分析结果（优点/缺点/建议） |

## 3. PDF 上传 + AI 解析

`uploadAndParse`（184 行）：

```
上传 PDF ──► AiService.extractTextFromPdf（PDFBox 提取文本）
              ──► AiService.parseResume（AI 抽取 16 字段）
              ──► 回填简历表单
```

- `uploadPdf`（150 行）当前为模拟路径（TODO，未真正落盘）。
- `parseResume`（253 行）可单独对已有简历触发 AI 解析。

## 4. 默认简历机制

- `setDefaultResume`（234 行）：将某份简历设为默认。
- `getMyDefaultResume`（82 行）：投递时自动取默认简历。
- 一个学生只有一份默认简历（切换时清除旧的标记）。

## 5. 数据级权限（教师 → 班级 → 学生）

`getStudentResume`（307 行）：教师只能查看自己班级学生的简历，校验学生是否在本班，否则返回无权限。

## 6. 简历完整度

`complete_score` 表示简历完整度（教育/技能/自评等维度加权），用于前端展示"简历完整度"进度条（详见班级模块 `getClassStudents`）。
