## 板块一：项目背景与目标（1 分钟）

### 核心话术

> "在当前的校企合作中，学生找工作、老师推荐岗位、企业招聘，这三端之间缺乏一个统一的数字化平台。传统的方式是老师手动在群里发招聘信息，学生一个个投简历，企业HR需要花大量时间筛选——信息分散、效率低、数据难以追溯。"
>
> "所以我们做了这个**校企招聘就业管理系统**，目标是让**学生、教师、企业HR**三方在一个平台上高效协同——学生可以看到精准的岗位推荐，老师可以管理班级就业数据，企业HR可以AI智能筛选简历。"

### 关键数据（背下来）

| 角色 | 核心痛点 | 系统带来的价值 |
|------|---------|-------------|
| 学生 | 不知道哪些岗位适合自己，投递后无反馈 | AI人岗匹配推荐 + 投递进度可追踪 |
| 教师 | 难掌握全班就业情况，推荐岗位低效 | 数据大屏 + AI批量解析JD + 一键推送给学生 |
| HR | 简历太多人工筛选耗时 | AI简历评分 + 自动排序 |

左侧额外画 **Redis** 和 **DeepSeek API** 两个框，用箭头连到 Spring Boot：

- **Redis** ← 用于 JWT 黑名单（退出即失效）
- **DeepSeek API** ← 用于 AI 简历评分 / 人岗匹配 / JD 解析

### 话术参考

> "系统采用前后端分离架构。前端有两个入口——PC端使用 **Vue 3 + Element Plus**，为管理员、教师和HR提供完整的后台管理功能；移动端使用 **uni-app**，方便学生和外出办公的教师随时随地使用。"
>
> "后端基于 **Spring Boot 2.7**，采用经典的三层架构：Controller 处理请求路由、Service 封装业务逻辑、MyBatis-Plus 操作 MySQL 数据库。"
>
> "**这里有一个亮点**：我们使用了 **JWT + Redis 黑名单方案**。用户登录后获得一个 Token，退出时 Token 被加入 Redis 黑名单。这样既实现了无状态认证，又解决了"退出后 Token 仍有效"的安全问题。"
>
> "安全方面，**手机号和身份证号等敏感字段使用 AES 加密存储**，即使数据库泄露也无法还原明文。密码采用 **BCrypt 不可逆加密**。"
>
> "**AI 能力**是系统的另一大亮点。我们在简历评分、人岗匹配和岗位描述解析三个场景中，调用了 **DeepSeek 大模型接口**，实现了 AI 自动解析 JD、智能打分和匹配度计算。"

### 重点代码片段（截图备用）

以下只展示**一个**核心代码——AI 人岗匹配逻辑，这是项目最大亮点。

```java
// AiService.java - 人岗匹配：多维度 AI 匹配度计算
public Map<String, Object> matchJob(String jobTitle, String jobDescription,
        String jobRequirements, String studentName, String resumeText) {
    // 设计多维度的提示词，让 AI 从 4 个角度打分
    String prompt = "你是一个招聘匹配专家。"
            + "请从以下维度评估学生与岗位的匹配程度：\n\n"
            + "## 岗位名称\n" + jobTitle + "\n\n"
            + "## 岗位描述\n" + jobDescription + "\n\n"
            + "## 学生简历\n" + resumeText + "\n\n"
            + "请严格按以下 JSON 格式返回（0-100 整数）：\n"
            + "{\n"
            + "  \"matchScore\": 整体匹配度,\n"
            + "  \"skillMatch\": 技能匹配度（技术栈重合度）,\n"
            + "  \"eduMatch\": 学历匹配度,\n"
            + "  \"expMatch\": 经验匹配度,\n"
            + "  \"majorFit\": 专业契合度,\n"
            + "  \"matchReason\": \"匹配理由\"\n"
            + "}\n"
            + "只返回 JSON，不要包含其他文字。";

    return callAI(prompt, "matchJob");
}
```

**讲解话术参考（约 20 秒）：**
> "这是人岗匹配的核心代码。我们设计了一套**多维度的评估提示词**，把匹配度拆成技能匹配、学历匹配、经验匹配和专业契合度四个维度，让大模型分别打分。比如一个计算机专业、会 Java 的学生，匹配 Java 后端的岗位，skillMatch 和 majorFit 就会很高。最终结果以结构化 JSON 返回，前端直接展示雷达图，一目了然。"

## 板块四：总结与反思（1-2 分钟）

### 技术收获

| 技术点 | 收获 |
|-------|------|
| **Spring Boot + MyBatis-Plus** | 学会了 RESTful API 设计规范、数据层CRUD的最佳实践 |
| **JWT + Redis** | 理解了 Token 认证机制与无状态/有状态认证的区别 |
| **Vue 3 + Element Plus** | 掌握了 Composition API、组件化开发和路由守卫 |
| **AI 接口集成** | 学会了大模型 API 调用和提示词工程（Prompt Engineering） |
| **前后端联调** | 理解了 CORS 跨域、接口文档、联调流程 |

### 踩坑经历（加分项！挑 2 个讲）

**坑 1：MyBatis-Plus 逻辑删除的坑**
> "在实现删除功能时，我们给实体类加了 `@TableLogic` 注解来实现逻辑删除。但删除时我们用的是 `updateById()` 方法——结果发现 `deleted` 字段根本不会被更新！查了文档才知道，MyBatis-Plus 的 `updateById` 会自动跳过逻辑删除字段，得用 `removeById()` 才行。前后排查了半小时才发现问题。"

**坑 2：AI 解析返回 JSON 格式不稳定**
> "大模型有时返回的 JSON 会包含 ` ```json ` 标记或者 Markdown 格式，直接解析会报错。我们加了一段 JSON 清洗逻辑——提取 `{}` 之间的内容再去解析，才解决这个问题。这也让我们意识到**提示词工程**的重要性。"

### 下一步计划

> "如果要继续开发，我们有三件事想优化：
> 1. **引入 WebSocket** 实现实时消息推送，学生投递后 HR 能立刻收到通知
> 2. **增加部署配置**，用 Docker 容器化一键部署
> 3. **完善数据大屏**，引入 ECharts 让就业数据可视化更丰富"
