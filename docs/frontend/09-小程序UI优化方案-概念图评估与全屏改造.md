## 二、概念图客观评估

### 总体判断

10 张概念图与现有 08 规范**同源同向**（主蓝 #165DFF、蓝色科技风），信息架构与现有代码高度一致——它不是一次「重画」提案，而是对现有设计方向的**精修参照**。其价值在信息架构与场景化卡片，其短板在工程细节（状态色语义、文字下限、图标体系、状态设计），需经规范过滤后吸收，不可照抄。

### 2.1 视觉风格一致性

**优点**
- 三角色（学生/教师/HR）共用一个设计语言：蓝色头部 + 白卡分组 + 底部 TabBar，角色间切换无割裂感。
- 每个屏有一个明确的视觉焦点（登录页情绪标题、首页 AI 横幅、面试页大分数），层级意图清晰。

**不足**
- **渐变滥用**：头部大渐变、AI 横幅渐变、登录按钮渐变、面试"再来一次"按钮紫渐变（与全项目「刻意不用紫」的 AI 色决策冲突），视觉过重。落地时应收敛：页面头部保留 hero 蓝渐变，AI 元素统一青渐变，按钮用实底主蓝。
- **图标风格混杂**：概念图里面性、线性、emoji 风并存。落地必须统一 uni-icons 线性图标 + 圆角方块浅色底容器（现有页面已是此模式）。

### 2.2 色彩与字体搭配

**优点**
- 主蓝贯穿操作语义（按钮、链接、选中态），绿/橙/红仅用于结果状态，方向正确。
- AI 匹配度用环形 + 大数字表达，比纯文字直观，已被代码 ScoreCircle 组件吸收。

**不足**
- **状态色语义未收敛**：概念图中"建议"红标签、匹配环绿/蓝/橙、分数绿色大对勾共用多种红绿，没有统一的语义映射表。落地按 08 规范：`#F53F3F` 唯一红、`#FF7D00` 唯一琥珀、`#00B42A` 唯一绿，评分环四档阈值 ≥80 绿 / ≥60 蓝 / ≥40 橙 / 其余红。
- **小字号越界**：图中大量 10~11px 注释文字，低于小程序可读性下限。落地按 token 最小档 12px（辅助说明），13/14 承担正文。
- **字重层级不明显**：标题与正文多为常规字重，落地按规范标题 600、正文 400/500。

### 2.3 布局与间距合理性

**优点**
- 卡片式分组 + 16px 页面边距 + 卡片内 16px 内边距，与 08 规范完全一致，迁移成本低。
- "漏斗式首页"（问候搜索 → 进度 → 行动 → AI 入口 → 推荐列表）符合求职用户旅程，信息排序合理。

**不足**
- **单屏信息密度偏高**：图7 个人中心塞入用户卡+统计行+菜单列表+功能网格+设置组，实机滚动过长且重复（菜单与网格功能重叠）。落地时合并去重，以「功能网格」为主、「设置组」收尾。
- **横向元素过多**：图2 漏斗 5 段、图5 顶部 4 项统计 + 4 个 tab 同屏，390px 宽度下文字会被挤压。落地需控制每行 ≤4 项，小字用 12px 并允许省略。
- 概念图未考虑**底部安全区**（iPhone 全面屏），落地时固定底栏与 TabBar 必须 `env(safe-area-inset-bottom)`（现有代码已做，保持）。

### 2.4 组件与交互设计

**优点**
- 场景化卡片是最大亮点："下一个面试"蓝卡、"优先行动"列表、"提升建议"卡，把数据转化为行动指引，值得全部落地。
- 匹配度圆环 + 三档语义（高度匹配/部分匹配/建议改进）把 AI 结果讲人话，降低了算法黑盒感。

**不足**
- **状态设计缺失**：全图无加载态、空态、错误态、下拉刷新说明。落地强制复用现有 LoadingState/EmptyState/ErrorState，每屏补齐三态。
- **按压反馈未定义**：落地按 08 规范全局 `opacity: 0.85` + 卡片 `scale(0.98)`（App.vue 已有，保持）。
- 部分组件语义重复：图4"排序 tab"与图5"状态 tab"视觉一致但行为不同，落地时统一 tab 样式、按行为区分数据即可，不要造两套视觉。

### 2.5 用户体验流畅度

**优点**
- 核心路径短：登录 → 首页 → 岗位详情 → 投递 → 查看进度，最多 4 步闭环；"查看投递进度/准备面试"等按钮都指向下一动作，无死路。

**不足**
- **回退路径缺失**：概念图均为正向流程，未设计"投递失败/网络错误/未登录态"的引导。落地时错误页 ErrorState 提供重试，登录失效统一跳登录页。
- 图6"查看练习记录"按钮后端**无练习记录存储**，不能硬接——先落地为空态占位（避免造数据），待后端补接口再启用。
- 图8 消息中心概念要求**日期分组**（今天/昨天/更早），现有代码是扁平列表，是概念图中真正值得补的结构性增强。

### 2.6 与小程序设计规范的契合度

**优点**
- custom 沉浸式头部 + 品牌色导航的做法合规（微信小程序允许），概念图顶部留白已考虑状态栏与胶囊。

**不足**
- 概念图未体现胶囊避让细节（右上角 "..." 胶囊区不能放可点元素）。现有 NavBar 已动态获取状态栏高度，保持。
- 概念图 TabBar 图标为自定义图形，落地统一 uni-icons + 选中指示条（现有 TabBar/HrTabBar 模式），不动结构与角标逻辑。
- 概念图未覆盖深色模式与无障碍，本项目不在范围内，记录为已知边界。

### 评估小结

| 维度 | 评分（5 分制） | 一句话结论 |
|---|---|---|
| 视觉风格一致性 | 3.5 | 方向统一，渐变与图标需收敛 |
| 色彩与字体 | 3.5 | 主色正确，状态色语义与小字号需按规范修正 |
| 布局与间距 | 4.0 | 卡片体系契合度高，需降密度、控横向元素 |
| 组件与交互 | 3.5 | 场景化卡片优秀，状态三件套（加载/空/错）缺失 |
| 体验流畅度 | 4.0 | 正向路径短而闭环，异常路径与个别功能缺后端支撑 |
| 小程序规范契合 | 4.0 | 头部/胶囊/安全区基本考虑，TabBar 需按现有实现统一 |

**总评**：概念图是合格的"氛围与信息架构参考"，约 70% 可直接吸收；30% 的工程细节（状态色、字号下限、图标、三态、紫渐变）必须以 08 规范为准纠偏。

## 三、整体设计风格定位

延续 08 规范定稿，不另起炉灶：

> **蓝色科技风 · 克制可信**——求职工具不是内容消费产品，视觉服务于"效率与信任"。
> - **蓝 = 操作**（#165DFF）：按钮、链接、选中态、进度。
> - **青 = 智能**（#0EA5E9 / #0284C7）：AI 功能专属，刻意不用紫色避开俗套。
> - **白卡 + 浅灰底**（#F7F8FA）：信息承载层，阴影三级克制。
> - **一屏一焦点**：每屏只允许一个渐变/大号视觉元素，其余卡片平铺。

| 文字四级 | 标题/次要/辅助/占位 | `#1D2129` / `#4E5969` / `#86909C` / `#C9CDD4` |
| 字号八档 | 12/13/14/15/16/18/20/24 | 最小 12px，按钮 15px/600，页面大标题 20px |
| 圆角四档 | 标签4 / 按钮8 / 卡片12 / 抽屉16 + 胶囊999 | `$uni-border-radius-*` |

## 六、交互细节优化点

1. **三态全覆盖**：每个数据页必须有加载骨架（LoadingState）、空态（EmptyState 带引导按钮）、错误态（ErrorState 带重试）；禁止自绘。
2. **按压反馈**：保持 App.vue 全局 `opacity: 0.85`；列表卡补 `transform: scale(0.98)` 微交互。
3. **AI 生成中状态**：青色 shimmer + 「AI 正在…」文案（interview-practice 现有模式推广到 ai-parse、ai-matches）。
4. **Tab 吸顶**：deliveries / messages / ai-matches 的 tab 栏滚动吸顶，提升长列表可操作性。
5. **数字动效克制**：统计数字不做滚动动画（工具产品求快）；匹配环保留现有描边动画即可。
6. **Toast 规范**：成功 `success` 图标、失败/校验 `none` + 具体文案；禁止「操作成功」无信息量的提示。
7. **登录失效**：401 统一清 token 跳登录页并 Toast「登录已过期」，不静默失败。
8. **安全区**：所有吸底按钮/TabBar 必须 `env(safe-area-inset-bottom)`（逐页核查）。

## 七、实施优先级排序

| 批次 | 内容 | 理由 | 验收 |

## 八、决策记录（已拍板，不再讨论）

1. 概念图为"氛围参考"：吸收信息架构与场景卡片，工程细节以 08 规范为准纠偏。
2. 首页漏斗保留 5 段（含"建简历"），不砍回概念图 4 段。
3. 教师/HR 头部统计口径对齐概念图，全部复用现有 dashboard 字段，不加后端接口。
4. 「查看练习记录」先做空态占位（后端无练习记录存储），不造数据。
5. 「最近面试」入口跳 deliveries 页，不新建页面。
6. 简历完整度保持前端本地计算（resumeCheck.js），不切换后端 complete_score 字段。
7. AI 匹配保持 4 档评分阈值，只调配色 token，不动语义。
8. 深色模式、无障碍、横屏不在本期范围。
