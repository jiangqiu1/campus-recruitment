## 2. teacher/AIMatch.vue（最复杂，818 行）

### 2.1 匹配主链路（岗位模式）

```
选岗位(+班级) → generateMatch(365) → 确认框(按学生数估算耗时)
  → 删旧数据 deleteMatchesByJob(404) → batchGenerateMatches(413, timeout 120s)
  → loadResults(454) 拉全量 → 前端切片分页 → updateStats 统计
```

### 2.2 关键函数

| 函数 | 行号 | 职责 |
|------|------|------|
| generateMatch | 365 | 批量匹配入口 |
| batchMatchByStudent | 523 | 学生模式：串行遍历岗位逐条生成 |
| loadResults | 454 | 拉结果 + 前端分页 + 统计 |
| updateStats | 591 | 计算 matched/pushed/viewed/avgScore/distribution |
| showCompare | 663 | 横向对比（雷达图） |
| matchPercent | utils/score.js | 已抽到共享契约层（`matchScoreToPercent`），0-1 → 0-100 |

### 2.3 图表

- 横向对比：echarts **radar 雷达图**（687-719 行），4 维（技能/学历/经验/专业）。
- 分数分布：纯 CSS 条形图（非 echarts）。

### 2.4 已知问题

1. ~~`userStore` 引入未使用、`selectedStudentObj` 死变量~~ ✅ 已修复（P2-12，2026-09-07）：已删除。
2. `matchStats` 初始结构（295 行）缺 `avgScore/distribution`，与 `switchMode` 重置结构（498 行）不一致。
3. **统计分页后失真**：`pushSingle` 调 `updateStats()` 不带参，统计只算当前页 10 条，非全量。
4. `pushAll` 只推当前页，非"全部未推送"。
5. ~~评分刻度不一致~~ ✅ 已修复：`matchScore`（0-1）经 `matchScoreToPercent` 统一转 0-100，子维度 `:percentage="val"`（0-100）与总分配色均走 `utils/score.js` 的 `scoreColor`。
6. `deleteMatchesByJob` 失败分支 `if (e !== 'cancel')` 判断错误（Error 对象 ≠ 'cancel' 恒真），永远误弹"删除失败"。
7. `loadResults` 一次拉全量再前端分页，数据量大时性能差。

## 3. hr/BatchResume.vue（488 行，评分核心）

### 3.1 评分流程

```
loadDeliveries(191, 串行 for 循环按岗位聚合投递)
  → 点"评分" showScoreDialog(286) 读历史评分
  → 有记录走 rescoreResume(330)，无记录走 scoreResume
  → 点"简历" viewResume(228) 打开 ResumeDetailDialog
```

### 3.2 关键数据结构

- `scoreData`（165-176 行）：混合展示与请求状态的胖对象（jobTitle/total/dims/comment/scoreLogId/loading/scoring）。
- 维度解析：已改用 `utils/score.js` 的 `parseScoreDetail`（兼容中文/英文 key，输出统一 `{total, comment, dims}`）。

### 3.3 已知问题

1. **"自动评分"逻辑放错位置**（237-257 行）：写在 `getByDelivery` 的 **catch** 里，只有接口抛错才触发；`code===200` 但 `data===null`（真实无评分）不会自动评分。
2. **导出 CSV 只导当前页**（389 行）：基于前端分页后的当前页，非全量。
3. `filterStatus` 清空后值可能为 `undefined`，过滤条件恒真导致列表变空（213 行）。
4. **文件名 BatchResume 但无批量入口**：只有单条评分，`batchScoreResumes/batchScoreByCompany` 未被使用。
5. ~~fillHrScoreData 与 showScoreDialog 重复实现 dimMap 解析~~ ✅ 已修复：统一改用 `parseScoreDetail`。

## 4. teacher/JobPosting.vue（372 行，JD 解析）

**AI 流程**：贴 JD → `aiParseJob`(226) → `aiParseAPI.parseJob` → 成功用返回字段填 `form`（241-250 行），失败降级本地正则解析（262-324 行）。

**已知问题**：
1. 文件首行含 BOM 字符（`\uFEFF`）。
2. 字段命名对齐：后端 `parsed.requirements`（复数）→ 前端 `form.requirement`（单数）；`parsed.skills` 数组 join 成逗号串。
3. 本地降级正则脆弱（deadline 只支持少数格式）。
4. 岗位表格用原生 `<table>`，无分页无 loading。

## 5. teacher/AIParse.vue（231 行）

**AI 流程**：选班级 → 选学生 → `doAnalyze`(157) → `aiParseAPI.analyzeResume(studentId)` → 展示 overallScore/strengths/weaknesses/suggestions。

**问题**：~~`overallScore` 用 0-100，与 AIMatch 的 0-1 刻度不一致~~ ✅ 已统一：AIMatch 的 matchScore 现已经 `matchScoreToPercent` 归一为 0-100，全项目评分口径统一为 0-100。

## 6. hr/JobAnalysis.vue（317 行）

**流程**：`loadJobScores`(131) 串行 N+1 逐岗位调 `getAverageScoreByJobId/getMatchDistribution/getDimensionScores` → 聚合 radarData + 柱状排名。

**已知问题**：
1. "投递总数"字段错配（159 行）：列名是投递总数，实际赋 `job.viewCount`（浏览次数）；`total` 变量算完没用。
2. 伪造雷达图数据（188-197 行）：无维度数据时用 `avg±固定偏移` 硬编码填充。
3. 图表无 resize 监听。

## 7. admin/AIStats.vue（262 行）

**流程**：`loadData`(98) `Promise.all` 并发拉 4 接口 → 前端按 teacherId/createdBy 聚合教师排行（136-178 行）→ 折线图 + 饼图。

**已知问题**：
1. ~~`overviewRes` 解构后完全未使用~~ ✅ 已修复（P2-14，2026-09-07）：删解构 + 无效的 `getOverview()` 请求 + import。并发接口从 5 个变 4 个。
2. **时区 bug**（210-212 行）：`d.toISOString()` 是 UTC，与本地时间比较会导致"今天"在下午 4 点前被算成"昨天"。
3. `t.id === teacherId` 严格相等，类型不一致时教师名显示"未知"。
4. 每接口 `size:500` 无分页，超 500 条被截断。

## 8. 跨页面共性问题（接口契约层）

1. ~~评分刻度不统一~~ ✅ 已修复（P2-7）：统一到 `utils/score.js`，展示层一律 0-100，`scoreColor` 阈值统一 90/75。
2. ~~scoreDetail 维度契约不统一~~ ✅ 已修复（P2-8）：`parseScoreDetail` 兼容中文/英文 key，三处（AIMatch/BatchResume/JobAnalysis）共用同一解析。
3. **列表分页普遍"后端一次拉全量、前端 slice"**：AIMatch、BatchResume 的 page/size 形同虚设。
4. **多个页面无 resize**：JobAnalysis、AIStats 图表不自适应。
