# 小程序全页面改造执行方案

> 2026-10-02 · 适用 job-miniprogram（uni-app + Vue3 setup，src/pages 下 47 个页面）
> 本文件是**逐页执行指令**：每个页面给出「现状问题 → 改造目标 → 具体改动 → 预期效果」，可直接交给 AI 严格逐项执行。
> 上位依据：`docs/frontend/08-小程序UI设计规范.md`（token 与组件规范）、`docs/frontend/09-小程序UI优化方案-概念图评估与全屏改造.md`（概念图评估与批次排序）。

---

## 〇、总体改造思路概述

**定位**：本次是「精修」，不是重画。项目信息架构已完成且与概念图一致，token 体系（`src/uni.scss`）已建好，改造目标是**让所有页面真正落到规范上**：消灭硬编码色、统一组件细节、补齐状态设计、给 AI 元素统一的青色视觉语言与克制的动效。

**五条铁律（每一页都适用，违反即返工）**：
1. **不改功能逻辑**：只动 template 结构与 style；script 中的接口调用、状态流转、跳转路由保持原样（新增纯展示区块除外）。
2. **不造 mock 数据**：有真实接口的接真数据；后端没有的模块做空态占位（EmptyState / Toast），不虚构。
3. **颜色只出自 token**：新增/替换样式一律用 `uni.scss` 变量；发现硬编码色按下表收敛。
4. **组件只复用不自绘**：空态 EmptyState、加载 LoadingState、错误 ErrorState、弹层 PopupDrawer、评分环 ScoreCircle。
5. **动效克制**：只做入场淡入、AI 微光 shimmer、关键节点脉冲、按压 scale 四类；不做数字滚动、不做无限装饰动画。

**硬编码色收敛映射表（全局查找替换的依据）**：

| 发现的值 | 替换为 | 语义 |
|---|---|---|
| `#EF4444` / `rgba(239,68,68,*)` | `$uni-color-error` `#F53F3F` / `$uni-color-error-light` | 双红合并 |
| `#F59E0B` / `rgba(245,158,11,*)` / `#FFF7E8` | `$uni-color-warning` `#FF7D00` / `$uni-color-warning-light` | 双琥珀合并 |
| AI 元素的蓝色（`#165DFF` / `$uni-gradient-primary` / `$uni-color-primary-light`） | `$uni-color-ai` `#0EA5E9` / `$uni-color-ai-strong` `#0284C7` / `$uni-gradient-ai` / `$uni-color-ai-light` | 蓝=操作，青=智能 |
| `10px/11px` 字号 | `$uni-font-size-xs` 12px | 可读性下限 |
| 2/3/6/10/20/24px 圆角 | 就近收敛 4/8/12/16 | 四档体系 |
| 评分阈值 85/70/50 | 80/60/40 | 与 ScoreCircle 统一 |

**全局通用规则（每页默认执行，页内不再重复写）**：
- G1 颜色/字号/圆角/间距按上表与 `uni.scss` 收敛，页面结束时 grep 硬编码十六进制色应只剩业务特殊值（如微信绿 `#07C160`）。
- G2 数据页三态齐全：加载 LoadingState（skeleton）、空态 EmptyState（带引导按钮）、失败 ErrorState（带重试）。
- G3 可点元素按压反馈：卡片 `transform: scale(0.98)` + transition 0.15s；列表行 scale(0.97)；图标按钮 opacity 0.85。
- G4 导航：custom 页统一 NavBar 组件（easycom 已自动注册）；原生导航页**禁止**再写 NavBar；custom 页禁止改回原生。
- G5 吸底元素（按钮/TabBar）底部 padding 必须含 `env(safe-area-inset-bottom)`。
- G6 AI 生成中状态：青色 shimmer + 「AI 正在…」文案（参照 interview-practice 现有模式）。
- G7 TabBar/HrTabBar 只调色值间距，不动结构、角标与跳转逻辑。
- G8 Toast 规范：成功 `icon:'success'`，失败/校验 `icon:'none'` + 具体原因文案。

**执行与验收约定**：按 09 方案的 P0 → P1-A → P1-B → P1-C → P2 顺序；每页改完单独 commit（信息格式 `style(miniprogram): <页面名> UI 精修`）；每页在微信开发者工具走一遍核心路径确认无回归。

## 一、学生端（18 页）

### 1.1 登录页 `student/login.vue`（P1-B）
- **现状问题**：①大标题 `font-size: 26px` 超出 hero 档（24px）；②「企业」角色卡复用 `person` 图标，与「学生」无法区分；③整体结构已达标，无需动布局。
- **改造目标**：字号入档、三角色图标可辨，保持品牌情绪页的完整性。
- **具体改动**：
  - 视觉：`.login-headline` 26px → `$uni-font-size-hero`（24px），行高 32px。
  - 视觉：企业角色卡图标 `person` → `shop`（学生 `person`、教师 `staff`、企业 `shop`）。
  - 交互：角色卡选中态加 `transition: all 0.2s ease`，切换有过渡；角色卡按压 scale(0.96)。
  - 内容：不变（微信一键登录保留现状逻辑）。
- **预期效果**：标题层级合规；三个门户一眼可辨；角色切换有跟手的过渡感。

### 1.2 学生首页 `student/home.vue`（P1-A，**已完成 2026-10-02，作为基准样例**）

### 1.3 岗位详情 `student/job-detail.vue`（P1-A）
- **现状问题**：①薪资 `$uni-color-error` 红色，在蓝色科技风中突兀；②岗位职责用「•」圆点，概念图为编号列表；③`matchVerdict`/`matchDims` 配色硬编码十六进制；④无匹配记录时 AI 卡整体隐藏（`v-if="matchRecord"`），出现内容断层；⑤缺 ErrorState（接口失败无兜底 UI）。
- **改造目标**：决策卡（AI 匹配）成为本页视觉锚点；信息层级对齐概念图；异常有兜底。
- **具体改动**：
  - 视觉：`.job-salary` 红色 → `$uni-color-primary`。
  - 内容组织：岗位职责列表「•」→ 自动编号（`v-for` index + 1 前缀，样式 13px 次要色、右间距 6px）。
  - 视觉：matchVerdict 三档（高度/部分/建议）与 matchDims 进度条颜色改 token：高 `$uni-color-success`、中 `$uni-color-primary`、低 `$uni-color-warning`；进度条轨道 `$uni-border-color-divider`。
  - 布局：`matchRecord` 为空时 AI 卡不隐藏，改渲染轻量占位（青色图标 +「暂无 AI 匹配结果」+「去生成匹配」文字按钮，点击 `uni.navigateTo` 到 `/pages/student/ai-matches`）。
  - 交互：顶部公司卡、底部分享/收藏按钮按压 scale(0.97)；收藏切换加 0.2s 过渡。
  - G2：页面加载失败时显示 ErrorState（重试调原加载方法）。
- **预期效果**：薪资不再刺眼；职责列表更易扫读；AI 卡任何状态下都在场，引导生成匹配；页面异常可恢复。

### 2.1 教师工作台 `teacher/home.vue`（P1-C）
- **现状问题**：①头部三指标「累计投递/班级学生/发布岗位」与概念图口径「待审核简历/班级学生/待处理」不符；②待办图标底色残留 `rgba(245,158,11,0.08)`、`rgba(239,68,68,0.08)`（旧琥珀/旧红）；③近期动态时间线已有真数据。
