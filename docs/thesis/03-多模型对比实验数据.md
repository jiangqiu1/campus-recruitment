# 论文素材三：多模型对比实验数据

> 数据来源：`ai_parse_log` 表（生产库真实调用，非构造数据），导出时间 2026-10-07。
> 复现 SQL 附文末。

## 一、总体对比

| 提供方 | 模型版本 | 调用次数 | 平均耗时 | 最快 | 最慢 | 降级次数 | 降级率 |
|---|---|---|---|---|---|---|---|
| 智谱 GLM | glm-4.5-flash | 10 | 10,019 ms | 2,340 ms | 26,910 ms | 0 | 0% |
| DeepSeek | deepseek-chat | 3 | 2,875 ms | 2,089 ms | 3,756 ms | 0 | 0% |

**结论 1（性能）**：DeepSeek 平均耗时约为 GLM 的 28.7%（2.9s vs 10.0s），速度优势显著；两者在本实验周期内降级率均为 0%，可用性相当。

## 二、分任务对比

| 任务 | GLM 次数 | GLM 平均耗时 | DeepSeek 次数 | DeepSeek 平均耗时 |
|---|---|---|---|---|
| 简历诊断（analyzeResume） | 3 | 16,126 ms | 2 | 3,268 ms |
| 就业洞察（insight） | 2 | 6,752 ms | 1 | 2,089 ms |
| 人岗匹配（matchJob） | 4 | 8,402 ms | — | — |
| 简历解析（parseResume） | 1 | 4,702 ms | — | — |

**结论 2（任务画像）**：诊断类任务（长简历输入）耗时差最大（约 5 倍）；洞察类任务两者均较快。GLM 单次方差较大（2.3s~26.9s），DeepSeek 方差小（2.1s~3.8s），对超时敏感的场景 DeepSeek 更稳。

## 三、文本质量对比（同一数据、同一 Prompt）

以「AI 就业洞察」为例，两模型对**同一份真实统计数据**的输出风格差异：

| 维度 | 智谱 GLM-4.5-flash | DeepSeek-chat |
|---|---|---|
| 分析切入 | 比例关系计算：师生比 3.85:1、岗位竞争比 4.7:1、投录转化率 19.15% | 人均行为：人均投递 1.74 次、未进入面试占比 42.6% |
| 关注焦点 | 结构性比例与企业服务能力 | 用户行为漏斗与处理效率 |
| 建议风格 | 组织专场招聘会 + 企业分享面试经验 | 扩大用户基数、提升企业响应效率 |

**结论 3（质量）**：两模型均严格引用真实数字、未出现编造；GLM 偏"比率洞察"，DeepSeek 偏"漏斗洞察"。实验中出现一次 GLM 对时间窗口方向表述错误（近7天/前7天颠倒）而 DeepSeek 正确——说明同一任务下模型可靠性存在差异，对比看板为模型选型提供了数据依据。

## 四、实验设计说明（论文方法论段可用）

1. **数据采集**：平台 AI 网关（AiService）对每次 LLM 调用自动记录 provider、model、task_name、latency_ms、mock_flag 至 `ai_parse_log`，无需人工埋点
2. **可控变量**：两模型通过相同的服务端网关调用，Prompt、max_tokens（1024）、temperature（0.3）一致；智谱通道额外启用 JSON 模式与思考链关闭（该模型特有参数）
3. **可靠性机制**：JSON 解析失败自动重试一次；重试仍失败降级为占位结果并标记 `mock_flag=1`，保证不向业务层返回损坏数据
4. **数据真实性**：统计上下文全部来自平台真实业务表（投递/用户/企业/岗位），Prompt 中要求"每条洞察必须引用至少一个具体数字，禁止编造"

## 五、复现 SQL

```sql
-- 总体对比
SELECT provider, model, COUNT(*) AS calls,
       ROUND(AVG(latency_ms)) AS avg_ms,
       MIN(latency_ms) AS min_ms, MAX(latency_ms) AS max_ms,
       SUM(CAST(mock_flag AS SIGNED)) AS mock_cnt
FROM ai_parse_log GROUP BY provider, model;

-- 分任务对比
SELECT task_name, provider, COUNT(*) AS calls, ROUND(AVG(latency_ms)) AS avg_ms
FROM ai_parse_log GROUP BY task_name, provider ORDER BY task_name;

-- 管理端可视化：数据大屏 → AI 使用统计 → 多模型对比看板
-- 明细导出：数据导出 → AI调用记录（多模型对比）
```
