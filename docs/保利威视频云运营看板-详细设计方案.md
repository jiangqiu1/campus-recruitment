## 详细设计方案

> 软件技术 · 工坊班实训课题 40 · 导师：陈婷
> 技术底座：校企合作项目「校园招聘就业平台」的工程经验复用

## 一、选题背景与意义

### 1.1 问题背景

保利威视频云平台已开放丰富的 API 接口和 AI 能力（智能字幕、智能翻译、AI 看、智能答疑等），但**如何将这些分散的能力与数据整合为运营人员可直接使用的决策工具，仍是一个待解决的问题**。

新媒体运营人员日常需要监测视频播放表现、用户画像、互动数据等多维指标，但面临三个现实痛点：

1. **数据分散**：播放数据、用户行为、互动数据散落在不同接口，需要人工拼接。
2. **AI 能力割裂**：智能字幕、智能翻译、AI 看、智能答疑各自独立，没有和运营数据打通。
3. **缺乏决策支持**：即便看到数据，也难以回答"这条视频为什么表现好、下一步该怎么做"。

### 1.2 技术契机

保利威开放平台同时提供**数据接口**（播放/用户/互动）与 **AI 能力接口**（字幕/翻译/AI 看/答疑），为"数据 + AI"的融合提供了基础。大语言模型的成熟，又为"智能洞察与运营建议"这一决策层提供了兜底与增强手段。

### 1.3 选题意义

- **工程价值**：为新媒体运营人员提供一站式决策工具，具备真实业务场景与合作伙伴（保利威）。
- **技术价值**：涉及第三方 API 集成、数据聚合、AI 能力编排、可视化等多项软件工程能力。
- **个人价值**：复用作者校企项目的数据大屏与 AI 集成经验，形成"招聘平台 → 视频运营平台"的能力迁移。

## 二、课题目标与范围

### 2.1 系统目标

基于保利威开放平台，设计实现一个新媒体运营数据分析看板，实现：

- **数据整合**：聚合播放表现、用户画像、互动数据等多维指标。
- **AI 能力集成**：将智能字幕、智能翻译、AI 看、智能答疑接进看板，成为运营可用的功能。
- **智能洞察**：结合数据与 AI，自动生成内容分析与运营建议，支撑数据驱动决策。

### 2.2 功能边界

| 维度 | 范围 |
|------|------|
| 必做 | 数据看板、AI 字幕/翻译/摘要/答疑功能、智能洞察建议、账号管理 |
| 暂不做 | 视频上传/转码（用保利威既有能力）、多租户、支付 |
| 视资源而定 | 保利威 AI 接口拿不全时，用 LLM（DeepSeek）替代实现部分 AI 功能 |

### 2.3 验收标准

| 能力 | 验收指标 |
|------|---------|
| 数据整合 | 接入播放/用户/互动三类数据，看板可展示 |
| 可视化 | 多维指标图表，含趋势、分布、漏斗 |
| AI 能力 | 字幕/翻译/AI 看/答疑中至少 2 项可用 |
| 智能洞察 | 能自动生成内容分析 + 运营建议 |
| 系统演示 | 无保利威实时数据时可用 mock 数据完整演示 |

### 2.4 与校企项目的关系

独立新系统，复用校企项目的技术栈与工程规范：

| 复用的能力 | 来源 |
|-----------|------|
| Spring Boot + MyBatis-Plus + MySQL + Redis 分层架构 | 校企项目后端 |
| Vue 3 + Element Plus + ECharts 数据大屏 | 校企项目 PC 端 |
| AI 调用管道（结构化 JSON + 降级 mock + 容错解析） | 校企项目 `AiService` |
| JWT 认证、AES 加密、操作日志 | 校企项目安全模块 |

│   InsightService：数据 × AI → 运营建议          │
│   ┌─────────────────────────────────────┐    │
│   │ 智能引擎（双引擎）                    │    │
│   │  首选：保利威 AI 能力接口             │    │
│   │  兜底：DeepSeek LLM（复用校企经验）    │    │

## 四、核心模块详细设计

### 4.1 数据接入模块

**功能**：对接保利威开放平台的数据接口，定时同步三类数据。

| 数据类别 | 指标 |
|---------|------|
| 播放表现 | 播放量、平均观看时长、完播率、播放趋势 |
| 用户画像 | 性别/年龄分布、地域分布、设备/终端分布 |
| 互动数据 | 点赞、评论、分享、弹幕、收藏 |

**同步策略**：`DataSyncService` 定时（如每小时）拉取，写入本地库，前端读本地库（解耦、避免频繁调第三方）。

### 4.2 AI 能力集成模块（灵魂）

**功能**：把保利威四项 AI 能力做成看板里的可用功能。

| AI 能力 | 在看板中的用途 |
|---------|--------------|
| 智能字幕 | 选中视频一键生成字幕，快速理解内容 |
| 智能翻译 | 视频内容/字幕/评论翻译成多语种（出海运营） |
| AI 看 | 自动生成视频摘要、亮点提取、关键词 |
| 智能答疑 | 运营以自然语言提问，结合数据回答（"这条为何完播率低"） |

**双引擎策略**（本课题关键设计）：

- **首选引擎**：保利威 AI 能力接口（若提供）。
- **兜底引擎**：DeepSeek LLM 复用校企项目 `AiClient` 管道，实现摘要、答疑、翻译等（字幕需 ASR，若保利威不提供字幕接口，则以"摘要/答疑/翻译"为必做 AI 能力）。

**价值**：即使保利威 AI 接口拿不全，系统的"智能洞察层"依然成立，**不塌成纯画图**。

### 4.3 可视化看板模块

**功能**：多维指标可视化。

- **核心指标卡**：总播放量、平均完播率、互动率、新增粉丝。
- **趋势图**：播放量/互动趋势（折线）。
- **分布图**：用户地域分布（地图）、性别年龄（饼/柱）。
- **漏斗图**：曝光 → 点击 → 观看 → 完播 → 转化。
- **视频榜单**：Top 视频、Top 掉队视频。

### 4.4 智能洞察与运营建议模块（决策层）

**功能**：`InsightService` 将数据 + AI 结合，生成结构化洞察。

**洞察维度**：

1. **表现归因**：某视频完播率低 → 结合 AI 看摘要，判断是"开头不吸引"还是"内容拖沓"。
2. **用户洞察**：地域/年龄分布 → 判断内容是否命中目标人群。
3. **内容建议**：结合热点与历史数据，AI 生成选题/标题/封面建议。
4. **告警**：数据异常（播放骤降、互动暴跌）自动触发告警。

**产出**：洞察报告（`insight_report` 表），前端以"智能洞察卡片"呈现。

## 五、保利威 API 集成方案（关键）

### 5.1 鉴权

采用保利威开放平台标准签名鉴权（appId + secret + timestamp 签名），以官方文档为准，封装在 `PolyvDataClient` / `PolyvAiClient` 内，业务层无感知。

### 5.2 数据接口

播放数据、用户行为、互动数据三类统计接口，定时拉取入库。

### 5.3 AI 能力接口

智能字幕、智能翻译、AI 看、智能答疑四类接口，按需调用（如选中视频时触发）。

### 5.4 降级与兜底

| 场景 | 策略 |
|------|------|
| 保利威接口超时/失败 | 返回缓存数据 + 前端标注"数据延迟" |
| 保利威 AI 接口不可用 | 切换到 DeepSeek LLM 兜底实现摘要/答疑/翻译 |
| 无任何实时数据（演示） | mock 数据完整演示看板 |

### 5.5 接口调用日志

每次调用记录 `polyv_api_log`（接口名、耗时、状态），用于排查与成本统计。

## 十一、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 保利威接口权限拿不到 | 数据源缺失 | LLM 兜底 + mock 演示，弱化实时数据 |

## 十二、预期成果与答辩亮点

### 预期成果

1. 可运行的新媒体运营数据分析看板（Spring Boot + Vue 3 + MySQL + Redis）。
2. 保利威数据接口集成 + 定时同步。
3. AI 能力集成（字幕/翻译/AI看/答疑，至少 2 项）。
4. 智能洞察与运营建议功能。

### 答辩亮点

1. **双引擎 AI 策略**——保利威 AI 优先、LLM 兜底，系统智能层不塌。

3. **数据整合工程**——多源数据聚合清洗、定时同步、解耦缓存。
4. **智能洞察闭环**——从数据到归因到运营建议的决策链。
5. **降级容错**——接口失败、无数据时系统仍可完整演示（复用校企 fallbackMock 思想）。
